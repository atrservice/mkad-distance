## 2. Суть продукта

«МКАД Дистанс» — публичный веб-калькулятор пробега спецтехники по автомобильным дорогам Москвы и МО:

- пробег считается ТОЛЬКО по дорогам (никаких прямых линий);
- точка привязки к МКАД — ближайший съезд нужной стороны (внешняя/внутренняя);
- адреса внутри МКАД = «зона 0 км»: ноги до съездов для них не добавляются;
- автоматический пересчёт при каждом подтверждённом адресе, без кнопки «Рассчитать»;
- PWA: установка на телефон как мини-приложение.

Этап 1 (готов и задеплоен): общедоступный калькулятор.
Этап 2 (запланирован): характеристики техники → расчёт стоимости → личный кабинет (потребует бэкенда).

Репозиторий: https://github.com/atrservice/mkad-distance (ветка main, GitHub Pages из корня).

## 3. Текущий статус (задеплоено и проверено)

Расчёт пробега по правилам раздела 8, точность сопоставима с Яндекс.Картами (±1 км).
Подсказки адресов: Dadata (если токен задан) + Nominatim; ввод координат в десятичном виде.
Карта: Leaflet 1.9.4 + тайлы OSM. РЕШЕНИЕ ПРИНЯТО: вариант «Яндекс.Карты» отклонён (раздел 18).
Тултипы-подсказки: шаблон «?» (раздел 11), закрытие по тапу по сообщению работает; обработчики на делегировании.
VPN-предупреждение: баннер `#netWarn` при недоступности сервисов карты.
Тумблер «Возврат на МКАД» с блокировкой при внутреннем последнем адресе.
СТОИМОСТЬ АРЕНДЫ: кнопка «Стоимость аренды» под тумблером → аккордеон секций «Маршрут» (в свёрнутом
заголовке общий километраж) / «Выбор техники» (карта прячется; при возврате — map.invalidateSize()).
Поток: тип техники → Шасси Шоссейное/Вездеход (кроме «Автомобиля прикрытия», по умолчанию Шоссейное)
→ характеристика (свой список и тултип на тип) → плашка цен «за смену/час/км» (редактируемые,
заполняются базовыми ценами по варианту и шасси). Сумма = смена + пробег × цена/км; пробег — из
последнего расчёта маршрута, обновляется живьём; смена варианта/шасси сбрасывает цены на базовые.
Базовые цены в js/vehicles.js — ЗАПОЛНИТЕЛИ до таблицы пользователя (помечены TODO).
Переключатель режимов «Калькулятор» / «Оформить заказ»: второй заблокирован до регистрации (тост),
тултип режима со ссылкой на презентацию (заглушка до предоставления ссылки).
PWA: manifest + service worker; иконки png 180/192/512 + svg.
Версия кэша sw на момент документа: `mkad-static-v21` (факт смотри в sw.js, правило инкремента — раздел 14).

## 4. Технологический стек

- Статический сайт без сборки и без бэкенда; чистый JS (ES-модули), HTML, CSS.
- Карта: Leaflet 1.9.4 с CDN unpkg (css+js), тайлы https://tile.openstreetmap.org.

- PWA: manifest.webmanifest + sw.js (precache оболочки, runtime-кэш same-origin и unpkg).
- Хостинг: GitHub Pages. Локальный запуск: `npx serve .` (файлом index.html НЕ открывать).

## 7. Геометрия МКАД и «ближайший съезд»

Источники и приоритеты (js/mkad.js):

1. `data/mkad-yandex.txt` — точные линии сторон. Внешняя сторона = кольцо БОЛЬШЕЙ площади (ringArea).
   Направления движения: внешняя = против часовой = км убывает; внутренняя = по часовой = км растёт.
2. Съезды: `MKAD_JUNCTIONS_OVERRIDE` (ручные) + распарсенные из Overpass узлы рамп;
   сторона узла = по близости к линии внешней/внутренней стороны.
3. Аварийно: `MKAD_FALLBACK_RING` (108 точек, по 1 на км) + боковое смещение 15 м к стороне адреса.

`mkadAccessPoint(address, inside, role, shiftKm=0.4)`:
- side = inside ? 'inner' : 'outer';
- если есть съезды этой стороны И shiftKm === 0.4 → ближайший узел съезда, bearingDeg = null;
- иначе точка на линии стороны: старт (role='start') сдвигается ВВЕРХ по ходу стороны
  (съезд впереди), финиш (role='end') — ВНИЗ по ходу (въезд позади); bearingDeg = направление движения стороны;
- иначе км-кольцо + боковое смещение 15 м к стороне адреса + bearings.

Парсинг файла: `txt.indexOf('[[[')` … `txt.lastIndexOf(']]]')`, JSON.parse среза; линии с <50 точками отбрасываются.

## 8. Бизнес-логика пробега (ФИНАЛЬНЫЕ правила; менять только по явной команде пользователя)

- Используются только ПОДТВЕРЖДЁННЫЕ адреса (выбран из подсказок или координат), строго префиксом:
  первый неподтверждённый адрес останавливает список (confirmedPrefix).
- `needStart` = первый адрес СНАРУЖИ МКАД → нога «МКАД → Адрес 1».
- `needReturn` = последний адрес СНАРУЖИ МКАД И тумблер «Возврат на МКАД» включён → нога «Адрес N → МКАД».
- Тумблер «Возврат на МКАД»: по умолчанию ВКЛ; если последний подтверждённый адрес ВНУТРИ МКАД —
  тумблер disabled + серый + подсказка `#returnToggleHint` («Последний адрес внутри МКАД — возврат к МКАД
  не рассчитывается») и его состояние ИГНОРИРУЕТСЯ (needReturn = false).
- Одиночный адрес внутри МКАД (тумблер любой) → пробег 0,0 км, статус «Без выезда и возврата к МКАД — 0 км»,
  на карте только маркер адреса, список участков скрыт.
- Матрица итогов:

| Первый | Последний | Тумблер | Маршрут |
|---|---|---|---|
| снаружи | снаружи | ВКЛ | МКАД → адреса → МКАД |
| снаружи | снаружи | ВЫКЛ | МКАД → адреса |
| снаружи | внутри | любой | МКАД → адреса |
| внутри | снаружи | ВКЛ | адреса → МКАД |
| внутри | снаружи | ВЫКЛ | адреса |
| внутри | внутри | любой | только между адресами |

- Пересчёт: дебаунс 250 мс; триггеры — подтверждение/удаление адреса, правка подтверждённого,
  переключение тумблера. Кнопки «Рассчитать» НЕТ.

## 9. Алгоритм расчёта (recalc в js/app.js)

1. confirmedPrefix(); updateReturnToggle();
2. needStart/needReturn по разделу 8;
3. buildPlan(endShiftKm): pts = [МКAD-старт?] + адреса + [МКAD-финиш?]; bearings = направления сторон для
   МКАД-точек, null для адресов; labels; mkadPts;
4. Если pts.length < 2 → ветка «0 км» (drawAddressesOnly);
5. Если needReturn: два кандидата финиша ПАРАЛЛЕЛЬНО (Promise.all): endShiftKm = -0.3 и +0.5;
   выбрать маршрут с меньшей distanceM;
6. loop-guard: если route.distanceM > суммы haversine по pts + 4000 м → досчитать кандидата endShiftKm = 0.9,
   взять минимум;
7. кэш маршрутов: Map, ключ = координаты|bearings, максимум 60 записей (session);
8. плашка: fmtKm (1 знак, ru-RU), «≈ N мин/ч» (fmtDur), статусная строка из формулировок раздела 8;
9. renderLegs (ноги: labels[i] → labels[i+1], км, мин);
10. маркеры МКАД рисуются ПО ФАКТИЧЕСКИМ концам геометрии маршрута (geom[0] и geom[last]),
    а не по расчётным точкам; адреса — синие круги с номерами; авто-зум fitBounds(padding 40).

## 10. Интерфейс: компоненты и поведение

- Строки адресов: номер, инпут (placeholder «Адрес или координаты (55.756, 37.617)»), крестик;
  ghost-строка (последняя пустая) создаётся автоматически, крестик скрыт (.is-ghost);
  после подтверждения фокус переходит в новую ghost-строку; бейдж «Внутри МКАД»/«Снаружи МКАД»
  (.addr-meta[data-state=in|out]); правка подтверждённого адреса сбрасывает подтверждение и пересчитывает.
- Подсказки: dropdown .suggest под инпутом; «Ищем…» → результаты; клавиатура ↑↓ Enter Esc;
  клик по подсказке = pointerdown (до blur); координаты: parseCoords (порядок lat,lon или lon,lat по диапазонам
  МО 54.5–57 / 35.5–39.5, вне региона — порядок Яндекса), reverse-подсказка с адресом, подтверждение сохраняет
  ИСХОДНЫЕ координаты точки.
- Плашка пробега: карточка в левой колонке; на мобильных position:fixed снизу, скрывается классом body.kb-open
  при фокусе в input/select/textarea; safe-area отступы.
- Тумблер: .toggle-row = [label.toggle (input#returnToggle + .toggle-box + .toggle-text «Возврат на МКАД»)]
  + маркер «?» (.help-wrap); ниже .toggle-hint#returnToggleHint.
- Карточка техники: комбобокс #vehicleInput (фильтрация по подстроке, список А–Я, selected-отметка),
  блок #specsForm (select/number/text из vehicles.js; значения на сессию в specValues);
  пока specs пусты — заглушка «Характеристики для «…» скоро появятся.».
- Карта: #map в .map-card; пунктирный контур внешней стороны МКАД (drawMkadRing);
  красные кольца = точки МКАД, синие круги = адреса.
- Баннер VPN: #netWarn (hidden) с кнопкой закрытия; триггеры показа: ≥3 ошибок тайлов (tileerror),
  ошибка поиска адреса, ошибка маршрута; текст просит отключить VPN и обновить страницу.
- Прочее: toast #toast; dialog установки PWA #helpDialog; кнопка «На главный экран» (beforeinstallprompt);
  служебных статусных строк в UI НЕТ (диагностика только console.info/console.warn).
  Переключатель режимов: .mode-card вверху левой колонки, сегменты .seg#modeSeg: «Калькулятор» (активен)
и «Оформить заказ» (.is-locked, НЕ disabled — клик показывает тост «появится после введения регистрации»);
в тултипе «Режим» ссылка на презентацию (заглушка до предоставления ссылки).
Сворачиваемые секции: #routeSection и #vehicleSection (.card.section). Заголовок .section-head: название
и, только в свёрнутом состоянии, итог: #routeKm (общий километраж, обновляется при каждом пересчёте) /
#vehicleSummary («Тип · вариант · шасси») + шеврон. Клик по свёрнутому заголовку разворачивает секцию
и сворачивает другую; развёрнутый заголовок не кликабелен; доступны с клавиатуры (Enter/Пробел).
Кнопка «Стоимость аренды» (#rentBtn) под тумблером возврата: setMode('rent') — «Маршрут» сворачивается,
карта и правая колонка прячутся (body.mode-rent), «Выбор техники» разворачивается и скроллится в кадр.
При возврате в режим маршрута обязательно вызывается map.invalidateSize() (иначе тайлы рисуются криво).
Поток выбора техники: комбобокс #vehicleInput (подпись «Тип техники») → тумблер «Шасси» .seg#chassisSeg
(Шоссейное слева, Вездеход справа; по умолчанию всегда Шоссейное; скрыт у типов с hasChassis=false) →
характеристика #specSelect (подпись #specLabel и тултип #specTip из vehicles.js) → плашка цен #pricePlate:
инпуты #priceShift/#priceHour/#priceKm (заполняются базовыми ценами по варианту и шасси, редактируемые)
и сумма #priceTotal: Сумма = цена за смену + Пробег (км) × цена за 1 км. Пробег — последний успешный
расчёт (при ошибке расчёта остаётся последнее известное значение); пока пробега нет — сумма = только смена
и пометка «пробег пока не рассчитан». Смена варианта или шасси сбрасывает поля на базовые;
ручные правки цен не сбрасываются до смены варианта/шасси.

## 18. Журнал ключевых решений (почему сделано так)

- Прямые линии запрещены бизнесом → только дорожный роутинг (OSRM).
- Петли OSRM на односторонних сторонах МКАД лечились последовательно: bearings по направлению стороны →
  сдвиг точки вверх/вниз по ходу стороны → два кандидата финиша параллельно (-0.3/+0.5) + loop-guard 0.9;
  итог сошёлся с Яндекс.Картами (±1 км).
- Точная геометрия сторон МКАД взята из выгрузки Яндекс.Карт (data/mkad-yandex.txt), т.к. Overpass/Nominatim
  нестабильны у пользователя; км-кольцо 108 точек оставлено аварийным фолбэком.
- «Внутри МКАД = 0 км» и блокировка тумблера — бизнес-правило пользователя (зона фикс-цены).
- ВАРИАНТ А принят пользователем 15.09.2026: карта остаётся Leaflet+OSM. Вариант «Яндекс.Карты» отклонён:
  бесплатный тариф JS API Яндекса — только некоммерческий, сервис коммерческий → платный договор;
  также текущий стек легально бесплатен для коммерции. Возврат к обсуждению возможен только при явной команде.
- Декоративные контуры фона и служебная строка «Схема МКАД…» убраны из UI по требованию пользователя
  (диагностика живёт в console).
- VPN не обходим кодом: показываем баннер-предупреждение (триггеры — ошибки тайлов/поиска/маршрута).
- Подсказки переехали на Dadata (скорость, RU-адреса, варианты МО), Nominatim оставлен фолбэком и для координат.
- Тултипы: закрытие по тапу по сообщению добавлено после жалоб на мобильном; hover ограничен
  @media (hover:hover), чтобы избежать «липкого» тултипа на тач-экранах.

## 19. Глоссарий

- Точка съезда / МКAD-точка — точка привязки маршрута к кольцу на нужной стороне.
- Внешняя / внутренняя сторона — противоположные односторонние полотна МКАД.
- Пробег — итоговая дистанция маршрута по дорогам.
- Нога (лег) — участок между соседними точками маршрута.
- Плашка — карточка/панель итогового пробега и статуса.
- Ghost-строка — автоматически создаваемая пустая строка ввода адреса.
- Подтверждённый адрес — адрес с координатами (выбран из подсказок или координаты).
- Loop-guard — проверка «дорожная дистанция не больше прямой + 4 км» с пересчётом кандидатом 0.9.
